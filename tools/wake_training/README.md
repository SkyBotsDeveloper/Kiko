# Hey Kiko Wake Model Training Toolkit

This folder contains Kiko's beginner-friendly, Colab-first workflow for a
free/open-source `Hey Kiko` wake model. It does not use Picovoice Porcupine,
paid SDKs, API keys, cloud wake detection, or paid hosted wake-word trainers.

You do **not** need to record your own voice for the first model. The default
path generates synthetic `Hey Kiko` positives with local/free TTS, prepares free
baseline negative/noise data, trains a TFLite model, and downloads the export.
Real voice samples can improve quality later, but they are optional.

The current backend trains a small TensorFlow/Keras CNN over log-mel features
and exports:

```text
tools/wake_training/output/hey_kiko.tflite
tools/wake_training/output/training_report.json
```

The model is not copied into Android assets automatically. Use
`install_model_to_app.py` only after export checks and real-device testing.

## Beginner Colab Path

Open:

```text
tools/wake_training/Kiko_Hey_Kiko_Training_Colab.ipynb
```

Then:

1. Runtime -> Change runtime type -> GPU.
2. Run setup dependencies.
3. Generate synthetic `Hey Kiko` positive samples.
4. Prepare free negative/noise data.
5. Run sanity training.
6. Optionally run balanced or quality training.
7. Run `export_check.py`.
8. Download `hey_kiko.tflite` and `training_report.json`.

The notebook is generated by `create_colab_notebook.py`; regenerate it after
editing notebook steps:

```bash
python tools/wake_training/create_colab_notebook.py
```

## Synthetic Positives

Generate wake samples without recording:

```bash
python tools/wake_training/generate_synthetic_positives.py --count 1000 --phrase "hey kiko"
```

The generator uses local `espeak-ng` or `espeak` when available. In Colab, the
notebook installs `espeak-ng` with apt. It supports phrase variants such as
`hey kiko`, `hey kee ko`, and `hey key ko`, plus speed, pitch, gain, and silence
padding variation. Output is 16 kHz mono WAV under:

```text
tools/wake_training/data/positive/hey_kiko/
tools/wake_training/data/validation/positive/
```

## Free Negatives and Noise

Prepare baseline negative/background data:

```bash
python tools/wake_training/prepare_free_negatives.py --profile sanity
```

This creates generated silence/noise samples and, when `espeak-ng` is available,
hard negatives such as:

- hey google
- hey siri
- okay google
- kiko
- hey key
- hey keto
- hello kiko

Speech Commands download support is optional:

```bash
python tools/wake_training/prepare_free_negatives.py --profile balanced --download-speech-commands
```

The automatic download can be large/fragile, so the default path remains local
generated negatives. You can manually place free public datasets in:

```text
tools/wake_training/data/negative/
tools/wake_training/data/background_noise/
```

## Training Profiles

`sanity`:

- small synthetic dataset
- small generated negative baseline
- verifies pipeline only
- not expected to be accurate

```bash
python tools/wake_training/train_hey_kiko.py --profile sanity --batch-size 8 --max-vram-gb 2.5
```

`balanced`:

- more synthetic voices/samples
- more negatives/noise
- GTX 1650-safe
- first usable model target

```bash
python tools/wake_training/prepare_free_negatives.py --profile balanced
python tools/wake_training/generate_synthetic_positives.py --count 3000
python tools/wake_training/train_hey_kiko.py --profile balanced --batch-size 12 --max-vram-gb 2.5
```

`quality`:

- larger synthetic dataset
- more augmentation
- hard negatives
- checkpoints/resume
- longer training
- safe batch sizes, no reckless GPU overload

```bash
python tools/wake_training/prepare_free_negatives.py --profile quality
python tools/wake_training/generate_synthetic_positives.py --count 6000
python tools/wake_training/train_hey_kiko.py --profile quality --batch-size 8 --max-vram-gb 2.5 --resume
```

## Optional WSL Path

Use this only if you want local training:

```bash
conda activate kiko-wake
cd /mnt/d/Kiko
python -m pip install -r tools/wake_training/requirements.txt
python tools/wake_training/generate_synthetic_positives.py --count 1000
python tools/wake_training/prepare_free_negatives.py --profile sanity
python tools/wake_training/train_hey_kiko.py --profile sanity --batch-size 8 --max-vram-gb 2.5
python tools/wake_training/export_check.py tools/wake_training/output/hey_kiko.tflite
```

If TensorFlow does not see the GPU, keep training on CPU or fix the local
CUDA/TensorFlow setup. Do not change the Android app for a local environment
problem.

## Dataset Layout

Generated and optional manual data uses:

```text
tools/wake_training/data/
  positive/
    hey_kiko/
  negative/
  background_noise/
  validation/
    positive/
    negative/
```

Do not commit datasets, generated samples, WAV files, checkpoints, or models.

## Export Check

Inspect the exported TFLite model:

```bash
python tools/wake_training/export_check.py tools/wake_training/output/hey_kiko.tflite
```

The current backend exports a log-mel feature model. The compatibility status
should be `feature-input-needs-adapter` until Android implements the same
feature extractor.

## Install Into Android App Assets

After export checks:

```bash
python tools/wake_training/install_model_to_app.py tools/wake_training/output/hey_kiko.tflite
```

Then from Windows PowerShell:

```powershell
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :app:installDebug
```

`app/src/main/assets/wake/hey_kiko.tflite` is gitignored by default.

## Android Compatibility

The Android runner currently accepts raw PCM-shaped TFLite input
`[1, samples]`. This training backend exports log-mel input shaped like
`[1, n_mels, frames, 1]`. Before real wake detection can be claimed, Android
needs either:

- a Kotlin feature extractor matching this Python preprocessing exactly, or
- a TFLite model that includes preprocessing and accepts raw samples.

Manual mic and Fake/Test wake remain the reliable fallback until real-device
wake detection, threshold tuning, and battery tests pass.
